# RC9 运行错误与启动诊断

RC9 同时包含工作空间单实例保护、RC8 后台邮件拉取及本次错误说明改进。重复启动同一工作空间会复用原服务；其他工作空间占用目标端口时明确退出，不启动重复后台任务。

## 邮件拉取

设置 → 邮箱显示任务编号、连接/登录/文件夹/读取邮件等失败阶段、可识别原因和处理建议。网络断线显示自动重连次数；重试耗尽后保留断点并提供继续入口。数据库占用可等待，空间不足、只读、I/O、完整性异常需按对应提示处理，不把所有 OperationalError 当作暂时网络错误。

单封邮件结构、编码或正文片段异常显示文件夹、UID 和固定原因；页面展示最近 5 条，任务状态最多保留最近 20 条。此记录不是所有历史异常的完整诊断档案。既有归档和去重规则不变。只凭错误类型无法确认根因时，明确说明尚未确定，不输出邮箱服务器原始响应或邮件正文。

## 软件更新

区分版本列表、update.json、update.sig 和 Windows ZIP；网络失败记录请求阶段、目标域名、尝试次数、已完整读取的字节数以及错误类型。DNS、证书、连接拒绝/关闭、超时、HTTP 限流/代理验证等有各自的处理建议。接收尚未完整返回的单次 read() 数据不计入已读取字节数。

小型发布元数据遇到瞬时断线可以从原 URL 重新读取一次；证书错误不自动重试。ZIP 已开始接收后不把新的完整响应追加到残包。大小、SHA-256、签名和来源构建验证仍须全部通过。

检查成功但没有适用版本与访问失败分开显示。最近一次更新请求失败记录保存在安装根目录 `.workthread-updates/request-error.json`，含时间、操作、说明和诊断编号；刷新/重启后可查，下次成功操作清除。新诊断不改变系统代理，也不能证明用户此前连接失败的具体原因。

普通未预期接口错误返回安全的固定说明和诊断编号，服务日志使用同一编号，不再在未知失败时一概承诺“原数据已保留”。快照不一致说明发生在哪个工作空间、为何停止切换及如何处理；不会绕过停写、备份、验签和回滚保护。

## 验证边界

本地 277 项自动测试通过。新增 19 项故障诊断回归覆盖合成邮件登录/断线/单封错误、数据库错误类别、元数据中断与重新读取、持久化诊断及敏感内容隔离。合成网页检查覆盖邮件原因和阶段、更新失败/刷新恢复、窄屏布局及无 JavaScript 异常。

Windows 原生构建和真实历史发布包升级结果以对应 Actions 运行及最终发布报告为准。本地模拟不等同于用户真实邮箱或 Windows 10/11 桌面环境验收；RC7 自身的旧错误提示须升级到 RC9 后才会改善。
