## 共用规则与自动化边界

- 两种模式使用同一份版本化待办指令、同一输出结构，以及同一套 Python 校验、写入和回执。WorkBuddy 使用文件队列；API 使用设置中选定的服务商与模型。API 需要发送所选原文和未关闭待办的相关字段，网页在执行前显示发送范围。
- 日期按原始录入时间和工作时区解释。缺少明确日期或日期模糊时保留原文，用户可填写截止日期或明确选择无限期。手动新增表单仍可独立使用。
- 用户选择处理近 90 天或历史邮件，每批最多 10 封，可逐封勾选。只展示已归档、尚未完成专用待办分析的邮件。批内按邮件时间处理，较晚的回复可引用本批较早创建的事项。
- 可能重复时由用户选主项、保留独立事项或忽略。证据明确且对应关系可核实的中间状态可自动更新；状态受人工保护、关联含糊、历史邮件或完成条件不满足时进入确认区。按“回复指定邮件”完成的任务需要本地已发送邮件、发件身份和回复关系匹配。
- 不完整批次、引文不符及过期结果不能部分推进处理进度。相同结果重放、切换执行模式和同步续传不会让同一封已成功处理的邮件在专用待办分析中重复记账。
