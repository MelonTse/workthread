# WorkThread 界面原则

根据使用反馈统一界面，后续页面沿用以下标准。

1. **任务优先**：先看到当前工作与主要操作；长说明、原始记录和高级配置按需展开。
2. **少步骤**：频繁切换使用可直接点击的标签；搜索提供清空；保存与当前内容相邻。
3. **紧凑但清楚**：数字使用短条，减少留白、标语、重复说明；保留业务标签与必要状态。
4. **上下文明确**：邮件对应自己的草稿，反馈对应具体草稿；客户、项目知识按对象组织，不混合展示。
5. **减少录入步骤**：新增 To Do 直接打开完整表单；保存成功自动关闭，失败保留输入。
6. **重要字段显著**：To Do 默认进入详情，标题位于顶部首行，截止设置紧随其后；具体日期或无限期必须明确选择。

## 各页实现

- 总览：紧凑数字、工作清单与建议；最近沟通直接进入对应邮件处理。
- 邮件：宽屏邮件列表、原文与回复并排，阅读区各自滚动；窄屏依次展示原文与草稿；标签切换多份草稿；反馈折叠，始终绑定草稿。
- To Do：搜索＋清空、状态标签、事项清单；详情／进展／来源分组，默认详情。状态、优先级、负责人并列；客户与项目并列；详情使用同一个“保存”提交并关闭，按钮位于填写内容之后的右下方。详情采用右侧非模态抽屉，可直接点击另一事项切换；未保存输入按事项保留在当前会话内，切换不自动保存，刷新丢弃。保存沿用原始 revision，外部更改不可被缓存草稿覆盖。
- 客户关系与知识：个人／客户／项目标签，按对象查看；搜索清空、就地添加与编辑，候选与确认状态保留。
- 设置：运行与 AI／邮箱／备份恢复分组；常用动作在首屏，高级字段折叠，恢复须先校验再确认。
- 快速录入：默认只有右下角小按钮，点击后直接进入新增表单，无标题预录入步骤。

## 截止与时间规则

HTML 新增在同一个表单内填写标题、截止设置及其他字段，点击“保存”才入库；用户明确选择的日期或无限期优先于标题中的相对日期词。rc2 所有新建业务入口均由 Python 校验截止设置；未知日期先确认，原始请求可保留在 intake/隔离材料中，不写入无效 To Do。旧记录未完善截止设置显示“待填写”；保存人工详情或修改状态前须选择日期或明确的无限期。不能把旧空值自动解释成无限期。

`no_due_date=true` 表示明确无限期；它和 `due_date` 互斥。数据库迁移 v2 增加该标志，旧记录默认 false，保留未填写状态。人工截止选择整体受保护，AI 不可静默覆盖；历史记录通过新版 ZIP 备份恢复时也保留这个区别；rc2 不负责恢复旧加密 7z。

登记进展时，发生时间按工作时区默认填入当前时间，支持人工修改；API 中人工日志省略该字段时使用当前时间，明确传空仍可记录未知时间。AI 不知道发生时间时保留空值，不伪造时间。

## 已确认的 v3 视觉与交互

- 深蓝固定导航、白色主工作面、玫红主要动作。邮件与知识对象列表采用浅灰底，选中项浅玫红加左侧色条；普通卡片仅轻阴影，右侧抽屉使用明显左向阴影。
- 不展示账户头像、个人工作空间切换或无意义标语。本地工作台无需登录，运行状态以实际数据为准。
- 总览数字使用紧凑横条；“待推进”“优先处理”“等待反馈”“已完成”可点击筛选，数量和清单共用口径，明确显示筛选范围并可清除。
- 导航可折叠为图标；折叠过程保持图标位置，文字淡出，保留可访问名称和悬停提示。减少动态效果偏好生效。
- 所有搜索框聚焦不增加高亮框，保留输入光标。其他输入保留内侧焦点边框，避免被滚动容器裁切；键盘按钮仍有焦点提示。
- 草稿反馈摘要占满一行，至少 40px 高，使用低调灰色悬停态。状态筛选、抽屉及反馈支持键盘操作。
- AI 操作用“加入 AI 分析队列”“加入 AI 重写队列”，不使用星星或暗示即时执行的文案。反馈保存与任务入队分别反馈；必须 WorkBuddy 处理、Python 回执完成后才视为结果已入库。
- v3 样板只是视觉参考。正式页面保留查重、合并、来源追溯、草稿版本、知识范围和备份校验等业务功能，任何成功提示均由真实接口结果触发。
