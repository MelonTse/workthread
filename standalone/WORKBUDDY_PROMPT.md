# 交给 WorkBuddy 的操作提示词

请协助我使用官方 WorkThread RC7 → RC9 独立升级工具 1.0.0，保留现有数据。不要使用网页更新或旧 bootstrap 再试，不卸载、不全新安装、不覆盖解压现有目录。

1. 先确认唯一实际安装根目录及运行版本；当前预期 `G:\WorkThread`、RC7，但以本机 BUILD_INFO 和进程为准。不要把 bootstrap 或旧下载包误判为另一个安装。发现多个无法区分的安装就报告。
2. 取得工具 ZIP 和发布的 SHA-256，核对完整 ZIP 的哈希后，解压到安装目录以外且非 OneDrive 的本地目录。核对 FILE_MANIFEST.sha256 和 BUILD_INFO.json，保留全部日志。本工具含官方 RC9 程序包、update.json、update.sig，不需要再访问 GitHub API 检查版本。
3. 只运行工具的 `--inspect`，显式传完整 `--install-root`、`--release-dir`；报告退出码。原 RC7 EXE SHA-256 必须为 91d5e1825b91c0c9bee9bd89a31eda92501245ee2c9d5b5e025fe9e9e2d38cae；RC9 ZIP SHA-256 必须为 8638fb190766b63422260c9ef4511a70d64839c01fc9ad5bba5d6b3c5a402ae6。签名验证由工具完成，不跳过、不改清单。
4. 帮我准备在资源管理器双击 Upgrade.cmd 的独立窗口，输入正确安装根目录，停在 Type UPDATE。此窗口必须独立于 WorkBuddy 工具会话。若启动被客户端安全策略拒绝，告诉我双击的完整路径，不绕过策略。
5. 停止你自己的邮件重试/值守任务，不创建任何定时任务。指导我正常关闭 WorkThread 服务，确认不再写入；不要仅关闭网页就当作服务已停。不要删除锁或强杀无法识别的进程。
6. 告知我退出 WorkBuddy，再由我在独立窗口输入 UPDATE。你不得代输入 UPDATE 或擅自使用 --confirmed，也不得修改 ACL、提权、把 DATS 改 DAT。工具先做同盘合成复制自检，通过后才开始真实快照。
7. 我回来报告结果后，只读检查本次 `logs\时间编号\result.json` 和失败记录。若成功，再从原 Start.cmd 启动一次，检查网页实际为 RC9、工作空间路径保持不变、原邮件/To Do/进展/知识/草稿/AI 交换文件和旧备份可用。不连接新邮箱，不发邮件，不触发 AI 批量处理，不建立定时任务。
8. 任一步失败，报告实际阶段、退出码、复制日志位置和差异摘要。不要把文件内容已复制等同于 ACL 或快照完整性通过。不要删除旧数据、失败快照或缓存。若中断，先报告事务状态；--recover 会拒绝覆盖切换后的新增数据，禁止绕过。

只提供必要的脱敏日志，不输出邮件正文、客户资料、授权码或 Token。Windows Server 自动化通过不等同于本机验收通过。
